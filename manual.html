1. 功能概述

Fusion Model Mapping（融合模型映射）是 CC-Switch 的跨供应商路由功能。它允许你将不同 Claude 模型类型自动路由到不同的 API 供应商，无需手动切换。

解决什么问题？

  • 痛点: DeepSeek V4 不支持多模态，但 Qwen3.6-Plus 支持。以前只能全局切换一个供应商，来回操作繁琐。
  • 方案: 配置好映射后，Claude Code 调用 claude-sonnet 时自动走 Qwen（多模态），调用 claude-haiku 时走 DeepSeek（低延迟），全程自动。

核心能力

能力说明
模型类型识别根据请求模型名自动分类（Haiku / Sonnet / Opus / Default）
跨供应商路由不同类型可指向不同的厂商 API
模型名映射将 Claude 内部的模型名替换为目标厂商的实际模型名
一键开关关闭后恢复原有行为，完全向后兼容

2. 入口位置

Fusion 标签页位于 Auth 和 Advanced 之间，标签栏第 4 个位置。

3. 开启融合路由

进入 Fusion 页面后，顶部有一个总开关：

  • ● ON — 融合路由生效，配置的映射规则对请求起作用
  • ● OFF — 融合路由关闭，所有请求走当前选中的供应商（默认行为）

开启后，页面底部会显示绿色脉冲指示灯 + "Fusion routing is active" 状态提示。

4. 配置模型映射

页面中部有 4 个模型类型卡片，每个卡片对应一种 Claude 模型分类：

卡片匹配规则何时生效
⚡ Default / Main不匹配以下任何类型的兜底Claude Code 使用未知/自定义模型时
🌸 Haiku模型名含 haiku（大小写不敏感）Claude Code 调用 claude-haiku-4-5 时
🎵 Sonnet模型名含 sonnet（大小写不敏感）Claude Code 调用 claude-sonnet-4-5 时
🎭 Opus模型名含 opus（大小写不敏感）Claude Code 调用 claude-opus-4-5 时

每个卡片包含两个配置项：

  1. Target Provider — 目标供应商（下拉框，从已配置的供应商中选择）
  2. Target Model — 目标模型名（文本输入，填入该供应商支持的模型名称）

配置完成后自动保存。未填写的类型不会被路由（仍走当前供应商）。

5. 工作原理

当融合路由开启后，每次 Claude Code 请求经过 CC-Switch 代理时：

① 收到请求
model: claude-sonnet-4-5 → ② 模型分类
检测到 "sonnet" → ③ 查找映射
{ providerId: "qwen", modelName: "qwen3.6-plus" } → ④ 转发请求
body.model = "qwen3.6-plus"
→ Qwen API 端点

关键特性

  • 优先级: 融合路由 > Claude Desktop 模型映射 > Provider 内置模型映射
  • 分类规则: 大小写不敏感。Haiku 优先于 Sonnet/Opus（模型名同时含多个关键词时先匹配 Haiku）
  • 未匹配时: 该类型未配置映射时，请求正常走当前选中供应商
  • API 格式: 目标供应商的 apiFormat（如 anthropic / openai_chat / openai_responses / gemini_native）会被正确应用，CC-Switch 自动完成格式转换

6. 实战示例

场景：同时使用 DeepSeek V4 + Qwen3.6-Plus 实现多模态支持

前提: 已将 DeepSeek 和 Qwen 分别配置为 CC-Switch 中的供应商（Settings → Routing 标签页可添加）。

配置:

模型类型Target ProviderTarget Model
Default / MainDeepSeekdeepseek-v4-pro[1m]
HaikuDeepSeekdeepseek-v4-pro[1m]
SonnetQwenqwen3.6-plus
OpusDeepSeekdeepseek-v4-pro[1m]

效果:

Claude Code 操作实际路由
普通对话 (haiku)→ DeepSeek (deepseek-v4-pro[1m])
图片识别 (sonnet)→ Qwen (qwen3.6-plus) 多模态
复杂推理 (opus)→ DeepSeek (deepseek-v4-pro[1m])

7. 常见问题

Q: 开启后请求仍然走原来的供应商？

检查：1) 开关是否为 ON；2) 模型名是否匹配（大小写不敏感，含 haiku/sonnet/opus）；3) 目标供应商 ID 是否存在。

Q: 融合路由和 Provider 内置的模型映射冲突吗？

不冲突。融合路由优先级最高。融合生效时会直接跳过 Provider 内置的模型映射。

Q: 融合路由是否支持故障转移？

暂不支持。融合路由直接将请求发给目标供应商，不经过故障转移队列。如需要故障转移，请在目标供应商的 Proxy 配置中开启。

Q: 日志中如何确认融合路由是否生效？

代理日志会显示 [Claude] Fusion: claude-sonnet-4-5 (Sonnet) → provider=Qwen, model=qwen3.6-plus。

Q: 配置保存在哪里？

保存在 ~/.cc-switch/settings.json 中的 fusionModelMapping 字段。

8. JSON 字段参考

配置在 ~/.cc-switch/settings.json 中的结构：

{
  "fusionModelMapping": {
    "enabled": true,
    "haiku": {
      "providerId": "deepseek-provider-id",
      "modelName": "deepseek-v4-pro[1m]"
    },
    "sonnet": {
      "providerId": "qwen-provider-id",
      "modelName": "qwen3.6-plus"
    },
    "opus": {
      "providerId": "deepseek-provider-id",
      "modelName": "deepseek-v4-pro[1m]"
    },
    "default": {
      "providerId": "deepseek-provider-id",
      "modelName": "deepseek-v4-pro[1m]"
    }
  }
}
字段类型必填说明
enabledboolean是总开关，false 时所有映射不生效
haikuobject否Haiku 模型类型的映射，含 providerId + modelName
sonnetobject否Sonnet 模型类型的映射
opusobject否Opus 模型类型的映射
defaultobject否兜底映射，不匹配以上类型时使用
providerIdstring是目标供应商在 CC-Switch 中的 ID（UUID 字符串）
modelNamestring是目标供应商对应的模型名

修改 JSON 后需重启 CC-Switch 生效。推荐使用 UI 界面配置以避免 ID 拼写错误。
